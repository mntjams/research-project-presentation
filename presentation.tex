\section{Introduction}
\begin{frame}
    \frametitle{Computational fluid dynamics}
    \begin{block}{What is CFD?}
        Computational fluid dynamics (CFD) is a branch of fluid mechanics that employs numerical techniques to predict fluid flow.\pause
    \end{block}
    \begin{itemize}
        \item CFD is applied to a range of research and engineering problems, including aerodynamics, weather simulation, and heat transfer analysis.\pause
        \item The basis of CFD are the \alert{Navier-Stokes equations}.
        \item These describe motion of fluids.
    \end{itemize}
\end{frame}

\begin{frame}
    \frametitle{Computational fluid dynamics}
    \begin{block}{Navier-Stokes equations}
        The Navier-Stokes equations are
        \[
            \rho (\frac{\delta \mathbf{u}}{\delta t} + \mathbf{u} \cdot \nabla \mathbf{u}) = -\nabla p + \mu\nabla^2 \mathbf{u} + F
        \]
        with
        \begin{itemize}
            \item fluid density $\rho$,
            \item velocity vector field $\mathbf{u}$,
            \item time $t$,
            \item pressure field $p$,
            \item dynamic viscosity $\mu$, and
            \item external forces $F$.
        \end{itemize}
    \end{block}
\end{frame}

\begin{frame}
    \frametitle{ELMM}
    \begin{itemize}
        \item Extended Large Eddy Microscale Model (ELMM) is a Large Eddy Simulation (LES) model for atmospheric flows.
        \item It is developed by the department of atmospheric physics.
        \item It is written in Fortran and parallelized using OpenMP, MPI, or hybrid MPI + OpenMP.
        \note {
            - Porting this code to GPUs could greatly benefit its performance
        }
        \item It computes how wind moves in the atmosphere.\pause
        \item In each time step a \alert{Poisson equation} must be solved.
    \end{itemize}
    \begin{block}{Poisson equation}
        The Poisson equation is
        \[
            \Delta \phi = b
        \]
        with
        \begin{itemize}
            \item pressure change $\phi$, and
            \item net outflow of predicted wind $b$.
        \end{itemize}
    \end{block}
\end{frame}

\section{PoisFFT}
\begin{frame}
    \frametitle{Poisson solver}
    \begin{itemize}
        \item PoisFFT is a library developed by the department of atmospheric physics to solve the Poisson equation.\pause
        \item PoisFFT was determined to be the best starting point for ELMM performance improve.\pause
        \item It solves the equation using an FFT-based method.\pause
        \note{
            - It is a self-contained library
            - Takes up noticable portion of the run-time.
        }
        \item Again, parallelized using OpenMP, MPI, or hybrid MPI + OpenMP.
        \note {
            - While measuring the performance, we encountered several hybrid configurations where PoisFFT straight up segfaulted
            - See next slide for configuration definition
            - With no existing documentation and PFFTs (PoisFFT multi-node FFT library) hybrid option being in development for the past 10 years, we gave up on that
        }
    \end{itemize}
\end{frame}

\begin{frame}
    \frametitle{Outside view of PoisFFT}
    \begin{itemize}
        \item The user first selects a solver based on dimensionality, floating-point precision, and grid uniformity.\pause
        \item Afeterwards, he defines a domain.\pause
            \begin{itemize}
                \item That is, number of grid cells,\pause
                \item grid lengths, and\pause
                \item boundary conditions (BCs).\pause
            \end{itemize}
        \item At last, he is allowed to solve the equation by supplying $b$.\pause
        \note{
            - $b$ is just an array of size (ns_x, ns_y, ns_z)
            - Both $b$ and $\phi$ can be surrounded by ghost cells
        }
    \end{itemize}
    \begin{exampleblock}{PoisFFT configuration example}
        \begin{itemize}
            \item 2D
            \item Single-precision
            \item Number of grid cells (8, 8)
            \item Lengths of the domain ($2 \pi$, $1.1 \pi$)
            \item BCs NeumannStag, NeumannStag, Periodic, Periodic
            \note {
                - In PoisFFT the notation is (x, y, z) for numbers and (west, east, south, north, bottom, top) for BCs
            }
        \end{itemize}
    \end{exampleblock}

\end{frame}

\begin{frame}
    \frametitle{Inside view of PoisFFT}
    PoisFFT has two phases:
    \begin{enumerate}
        \item \alert{initialization}, and
            \begin{itemize}
                \item Precompute the normalization factor and eigenvalues,
                \item prepare FFT plan (or plans), and
                \item allocate workspaces.
            \end{itemize}
        \item (repeated) \alert{execution}.
            \begin{itemize}
                \item Apply forward FFT,
                \item divide every element by a sum of pre-computed eigenvalues,
                \item apply backward FFT, and
                \item normalize the result.
            \end{itemize}
    \end{enumerate}
\end{frame}

\begin{frame}
    \frametitle{Inside view of PoisFFT}
    \begin{itemize}
        \item It became apparent that despite the initially simple outline, this will not be easy...\pause
        \item PoisFFT has \alert{no documentation} and only limited usage guide.\pause
        \item There are $\sim 140$ lines with comments in the $\sim 10 000$ lines of code.\pause
        \item Many (function, variable, etc.) names are non-descriptive.\pause
        \note {
            - D is a solver.
            - D1D is a 1D solver, but we never use it to solve anything, it is used to just hold data.
            - tmp1, tmp2, ctmp1, ctmp2
        }
        \item The architecture is very simple.\pause
        \begin{itemize}
            \item If-else block in every function!
            \item These sometimes span hundreds of lines.
            \note {
                - It is entirely possible to create a solver without an error but the solver does nothing on each Execute - TODO test this is true
                - They are interleaved with ifdefs to form if-else blocks based on compile time definitions
            }
        \end{itemize}
    \end{itemize}
\end{frame}
